## Quick Reference — Helpicon DevOps (EKS + Terraform + Jenkins)
- Designed and maintained a 3-account AWS strategy (DevOps / Staging / Production) with full infrastructure-as-code via Terraform covering EKS, RDS, ECR, and S3
- Implemented a Jenkins + Kaniko (ECS Fargate) build pipeline — no Docker-in-Docker, reproducible container builds triggered by git tag (staging) or main branch push (production)
- Automated Prisma database migrations as part of every deployment startup sequence, ensuring schema and application code stay in sync across environments
- Deployed two Kubernetes CronJobs for background automation: hourly payment status checks and 5-minute Workamo contractor sync — decoupled from the main API pod
- Managed Terraform remote state with S3 + DynamoDB locking and encrypted state files; parameterized all environment differences via `.tfvars` for zero-code-change environment promotion
- Stack: Jenkins, Kaniko, AWS EKS, Terraform, ECR, RDS PostgreSQL 14, S3, Kubernetes

# DevOps Infrastructure Summary - Helpicon Payment Service

## Executive Summary

This payment microservice uses a modern cloud-native DevOps setup with **Jenkins** triggering builds via **Kaniko** (containerized Docker builds), deploying to **AWS EKS** (Kubernetes) with infrastructure managed by **Terraform**. The system operates across three AWS accounts (DevOps, Staging, Production) in the EU-North-1 region.

## How It Works

### 1. Deployment Trigger

**For Staging:**
```bash
git tag -f staging
git push -uf origin staging
export ENV=staging && make k8s_apply
```

**For Production:**
```bash
export ENV=production && make k8s_apply
```

The system monitors:
- **Staging:** Git tag `refs/tags/staging`
- **Production:** Git branch `refs/heads/main`

### 2. Build Pipeline (Kaniko)

When a deployment is triggered:

1. **Preparation Phase:**
   - Fetches Kaniko task templates from BitBucket DevOps repository
   - Creates/updates IAM role `kaniko_ecs_role` with ECR push permissions
   - Gathers all secrets from environment files (`staging.mk`, `production.mk`)

2. **Build Phase (ECS Fargate):**
   - Runs Kaniko builder in DevOps AWS account
   - CPU: 2048, Memory: 4096 MB
   - Clones code from BitBucket
   - Builds Docker image with:
     - Node.js 20
     - Puppeteer + Chromium (for PDF generation)
     - Prisma ORM
     - All environment variables baked in
   - Resources: 2 vCPU, 4 GB RAM
   - Timeout: Polls until task stops

3. **Push Phase:**
   - Pushes image to target environment's ECR
   - Image tag: `helpicon-payments:latest`

### 3. Kubernetes Deployment

Once the image is built:

1. **Cluster Access:**
   - Discovers EKS cluster in target AWS account
   - Updates local kubeconfig with credentials

2. **Secret Management:**
   - Deletes old ECR pull secret
   - Creates new `regcred` secret with fresh ECR token

3. **Application Deployment:**
   - Applies all Kubernetes manifests from `infra/k8s/{env}/`
   - Performs rolling restart: `kubectl rollout restart deployment payments-depl`

### 4. What Gets Deployed

**Main Application:**
- **Deployment:** `payments-depl` (1 replica)
- **Service:** `payments-srv` (ClusterIP on port 3000)
- **Image:** Always pulls latest from ECR
- **Startup:** Runs Prisma migrations → starts Node.js server

**Automated Jobs:**
1. **Payment Release Cron** (every hour):
   - Checks and updates payment statuses
   - Processes Workamo releases
   - Command: `node src/crons/checkAndUpdatePayments.js`

2. **Workamo User Sync** (every 5 minutes):
   - Verifies contractor accounts in Workamo
   - Command: `node src/crons/checkWorkamoUsers.js`

## Infrastructure Components (Terraform)

### Database (RDS)
- **Engine:** PostgreSQL 14
- **Database Name:** `HelpiconpaymentsRds`
- **Instance Class:**
  - Staging: `db.t4g.micro`
  - Production: (defined in production.tfvars)
- **Credentials:** `helpicon` / `Helpicon`
- **Network:** Private subnets, VPC security group
- **Backups:** Daily at 21:00-22:00 UTC (2-day retention in staging)

### Container Registry (ECR)
- **Repository:** `helpicon-payments`
- **Features:** Image scanning, mutable tags
- **Policy:** Open access for push/pull (all AWS principals)

### Storage (S3)
- **Bucket:** `helpicon-service-payments-{env}`
- **ACL:** Public read (for receipts and documents)
- **Purpose:** PDF receipts, invoice storage

### State Management
- **Backend:** S3 bucket + DynamoDB locking
- **State Bucket:** `helpicon-payments-tf-state-{env}`
- **Lock Table:** `tf-lock-payments-{env}`
- **Encryption:** Enabled

## Security Overview

### Current Setup
✅ **Good Practices:**
- Infrastructure as Code (Terraform)
- Separate AWS accounts per environment
- VPC isolation for databases
- Encrypted Terraform state
- Image scanning enabled on ECR

⚠️ **Security Concerns:**
1. **Secrets in Git:**
   - API keys stored in `staging.mk` and `production.mk`
   - Database credentials hardcoded
   - BitBucket access token in `kaniko.mk`

2. **Access Controls:**
   - ECR policy allows all AWS principals (`*`)
   - S3 buckets are public-read
   - No secrets rotation mechanism

3. **Build-Time Secrets:**
   - All secrets baked into Docker image as environment variables
   - Secrets passed as Kaniko build args

### Recommended Improvements
1. **Migrate to AWS Secrets Manager or Parameter Store**
2. **Use IAM Roles for Service Accounts (IRSA) in EKS**
3. **Implement secrets rotation**
4. **Restrict ECR policy to specific AWS accounts**
5. **Use runtime secret injection instead of build-time**
6. **Enable AWS CloudTrail and GuardDuty**

## Cost Considerations

### Current Resources (Staging)
- **EKS Cluster:** ~$75/month (cluster fee)
- **RDS db.t4g.micro:** ~$15-20/month
- **ECS Fargate (Kaniko):** Pay per build (~$0.10-0.20 per build)
- **S3 Storage:** Variable based on usage
- **ECR Storage:** ~$0.10/GB per month
- **Data Transfer:** Variable

**Estimated Monthly Cost (Staging):** $100-150

### Production Considerations
- Should use larger RDS instance (db.t4g.small or larger)
- Consider Reserved Instances or Savings Plans
- Enable RDS Multi-AZ (+100% RDS cost)
- Multiple pod replicas (+EC2 node costs)

## Troubleshooting Guide

### Build Failures
```bash
# Check Kaniko task status
aws ecs describe-tasks --cluster default-cluster \
  --tasks <task-arn> --profile helpicon-devops-jenkins

# View build logs (if CloudWatch configured)
aws logs tail /ecs/kaniko-task --follow
```

### Deployment Issues
```bash
# Check pod status
kubectl get pods

# View pod logs
kubectl logs -f payments-depl-<pod-id>

# Check pod events
kubectl describe pod payments-depl-<pod-id>

# Manual rollout restart
kubectl rollout restart deployment payments-depl
```

### Database Connection Issues
```bash
# Test RDS connectivity from pod
kubectl exec -it payments-depl-<pod-id> -- bash
nc -zv <rds-endpoint> 5432

# Check security groups
aws ec2 describe-security-groups \
  --filters "Name=group-name,Values=helpicon-payments-postgres-sg"
```
