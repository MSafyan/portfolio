Company: Helpicon is a Swedish company based in Malmö, operating as Helpicon AB. It's a digital platform (app and website, helpicon.se) that connects people and businesses with verified local "Helpers" for tasks like cleaning, babysitting, pet care, deliveries, and minor repairs. ## Backend Architecture

### Microservices Design
- Service-oriented architecture with separate services for:
  - User management & authentication
  - Service provider onboarding & verification
  - Booking & scheduling engine
  - Payment processing & commission management
  - Messaging & notifications
  - Admin dashboard & analytics

- PostgreSQL database with multi-tenant data isolation
- RESTful APIs with JWT token-based authentication
- Input validation, error handling middleware, rate limiting
- Proper foreign keys, indexes, and query optimization

### Payment Integration - Stripe & Swish
- Stripe for subscription billing and card payments
- Swish for instant mobile payments (Nordic market)
- Implemented marketplace commission logic:
  - Platform fee calculation (percentage-based)
  - Automatic split payments to service providers
  - Payout scheduling and reconciliation
- Webhook handlers for payment events:
  - payment_intent.succeeded → update booking status
  - payment_intent.failed → notify user, retry logic
  - subscription.renewed → extend service access
  - subscription.canceled → downgrade account
- Subscription tier logic (Basic/Premium) with feature gating
- Refund handling and dispute management
- PCI compliance patterns and secure token storage

### Messaging - Twilio Conversations Integration
- Secure user-to-provider messaging via Twilio Conversations API
- Message persistence in PostgreSQL with full audit trail
- Multi-tenant isolation to prevent cross-talk between bookings
- Read receipts and typing indicators
- File attachment support (images, PDFs) with S3 storage
- Push notifications for new messages
- Message search and history retrieval
- Conversation archiving when booking completes

### Authentication & Authorization
- Multi-role system: Admin / Service Provider / Customer
- JWT token-based auth with refresh token rotation
- Password hashing using bcrypt (12 rounds)
- Email verification flow with secure tokens
- Password reset with time-limited tokens
- Session management with Redis for token blacklisting
- Role-based access control (RBAC) middleware
- Admin endpoints protected with IP whitelisting

### Admin Workflows
- Service provider approval/suspension system
- User account management (suspend, delete, restore)
- Platform analytics dashboard:
  - Active users, bookings, revenue metrics
  - Service provider performance tracking
  - Payment success/failure rates
- Reported content moderation queue
- Email notification triggers for approval events
- Bulk operations for user management

### Key Metrics & Performance
- Handled 10,000+ active users
- 500+ verified service providers
- 99.8% payment success rate
- Average API response time: <200ms
- Database queries optimized to <50ms for most endpoints
- Zero data breaches / security incidents

## DevOps & Infrastructure

### AWS Deployment Architecture
- ECS (Elastic Container Service) for container orchestration
- Auto-scaling groups:
  - Min 2 instances, max 10 based on CPU/memory
  - Scale-up at 70% CPU, scale-down at 30%
  - CloudWatch alarms for anomaly detection
- RDS PostgreSQL with Multi-AZ deployment for high availability
- S3 for file storage with CloudFront CDN
- Application Load Balancer with health checks
- VPC with private subnets for database security
- CloudWatch for logging and monitoring
- AWS Secrets Manager for credential management

### Docker Containerization
- Multi-stage Docker builds:
  - Build stage: npm install, TypeScript compilation
  - Production stage: minimal runtime image (Node Alpine)
  - Image size reduced from 1.2GB to 180MB
- Docker Compose for local development environment
- Container health checks and graceful shutdown handling
- Environment-based configuration (dev/staging/prod)

### CI/CD Pipeline - Bitbucket Pipelines
- Automated pipeline triggered on every commit:
  1. Run linting (ESLint)
  2. Run unit tests (Jest) - 85%+ coverage required
  3. Run integration tests
  4. Build Docker image
  5. Push to ECR (Elastic Container Registry)
  6. Deploy to staging (auto)
  7. Deploy to production (manual approval)

- Branch naming convention: PROJ-123-feature-name (Jira integration)
- Blue-green deployments for zero-downtime updates
- Automated database migration scripts (Knex.js)

## Key Technical Workflows to Reference

Payment Flow:
User books service → Stripe payment intent → webhook confirmation → update booking status → split payment (platform fee + provider payout) → provider notification

Messaging Flow:
User initiates chat → Twilio Conversation created → messages persisted to PostgreSQL → push notification → provider responds → S3 file upload for attachments

Deployment Flow:
Code commit → Bitbucket Pipeline triggered → tests run → Docker build → ECR push → ECS rolling update → health check validation → complete (11 min total)

Admin Approval Flow:
Provider submits profile → enters approval queue → admin reviews → approve/reject action → email notification → provider status updated → analytics dashboard updates
