# Pink Chicken Data Warehouse Engineering Project
## Enterprise Data Integration & Analytics Solution

### **Project Overview**
Architected and implemented a comprehensive data warehouse solution for Pink Chicken, a multi-channel children's apparel retailer, integrating disparate systems (Shopify POS/E-commerce and Apparel Magic WMS) into a unified analytics platform supporting 10+ retail locations and e-commerce operations.

### **Technical Architecture**

#### **Cloud Infrastructure (Microsoft Azure)**
- **Azure Data Factory (ADF)**: `adf-pinkchicken-eus2` - Orchestrated ETL pipelines with complex API integrations
- **Azure SQL Database**: `asqldb-pinkchicken-eus2` - Centralized data warehouse with optimized schemas
- **Azure Storage Account**: `sapinkchicken` - Staging area for JSON data transformation
- **Virtual Network**: `vnet-pinkchicken-eus2` - Secure private network with endpoints
- **Resource Group**: `rg-pinkchicken-eus2` - Consolidated resource management in East US 2

#### **Data Integration Strategy**
**Multi-Source Integration Challenge**: Unified inventory and sales data from:
- **Shopify REST API**: 10 retail store locations + e-commerce platform
- **Apparel Magic API**: Warehouse management system with virtual warehouses
- **Complex Deduplication**: Prevented double-counting of e-commerce inventory across systems

### **Technical Implementation**

#### **Advanced ETL Pipeline Architecture**
**Azure Data Factory Pipelines Developed**:
- `AM_Copy_Customer` - Apparel Magic customer data with nested JSON transformation
- `Copy_Endpoint_Data_Incremental` - Incremental data loading with timestamp-based controls
- `PL_Shopify_To_SQL` - Shopify API integration with rate limiting and pagination
- `Copy_Data_Product` / `Copy_Data_Order` - Specialized product and order data pipelines

#### **API Integration Complexities Solved**
**Shopify API Integration**:
- Implemented pagination with RFC 5988 standard (Link headers)
- Managed rate limiting (40 requests/app/minute bucket)
- Complex inventory level queries requiring location_ids batching
- Historical data extraction with date range filtering

**Apparel Magic API Integration**:
- Unix timestamp + API token authentication
- New mandatory pagination system with `last_id` mechanism
- Rate limiting management (4 requests/second)
- Virtual warehouse reconciliation logic

#### **Data Warehouse Schema Design**
**Dimensional Modeling Approach**:
- **Fact Tables**: Sales transactions, inventory snapshots, order details
- **Dimension Tables**: Products, customers, locations, time dimensions
- **Bridge Tables**: Complex many-to-many relationships for product variants
- **Control Tables**: `data_load_control` for incremental processing tracking

#### **Advanced Data Processing Features**
**Incremental Data Loading**:
```sql
-- Data load control mechanism
Select * from data_load_control where table_name = '@{pipeline().parameters.table_name}'
```

**Snapshot Strategy for Historical Analysis**:
- Implemented daily inventory snapshots with date stamping
- Enabled month-over-month and year-over-year trending analysis
- Addressed lack of historical data in source systems

**JSON Data Transformation**:
- Complex nested JSON parsing from both APIs
- Dynamic schema mapping with auto-table creation
- Parameterized table names for flexible pipeline execution
